# Архитектура проекта синхронизации Microsoft To Do и Kaiten

## Общая архитектура

Проект построен по модульной архитектуре с четким разделением ответственности между компонентами:

- **Конфигурация** (`src/config/`) - управление настройками приложения
- **Исключения** (`src/exceptions/`) - определение пользовательских исключений
- **Утилиты** (`src/utils/`) - вспомогательные функции для работы с датами и хэшами
- **Клиенты** (`src/clients/`) - слои абстракции для работы с внешними API
- **Движки** (`src/engines/`) - бизнес-логика синхронизации
- **Точка входа** (`src/main.py`) - запуск приложения

## Компоненты

### Клиенты API

#### Microsoft To Do Client
- Аутентификация через MSAL
- Получение и обновление задач
- Управление списками задач

#### Kaiten Client
- Аутентификация через API-токен
- Получение и обновление карточек
- Управление карточками в доске

### Движки синхронизации

#### Основной движок (SyncEngine)
- Двусторонняя синхронизация задач
- Использование хэшей для определения изменений
- Обработка новых, измененных и удаленных задач

#### Движок принудительной синхронизации (ForceSyncEngine)
- Принудительная синхронизация без учета хэшей
- Обновление всех задач в обе стороны
- Полное сопоставление задач между системами

## Поток данных

1. Приложение загружает конфигурацию
2. Получает токены доступа к API
3. Загружает текущее состояние задач из обеих систем
4. Загружает маппинг задач из файла
5. Выполняет синхронизацию в соответствии с выбранной стратегией
6. Сохраняет обновленный маппинг
